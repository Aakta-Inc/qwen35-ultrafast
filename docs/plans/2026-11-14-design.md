# Design and provenance — 2026-11-14

User-authorized scope: create a separate public Qwen3.5-4B repository, baseline on the available GPU, then optimize; original code only in Rust/CUDA/C/C++. No Baseten code copying. Public repository belongs to Aakta-Inc.

Architecture: Rust owns benchmark inputs, lifecycle, measurement, artifact validation and reporting. A pinned C++/CUDA llama.cpp backend is the initial external reference. Independent CUDA experiments are added only with numerical reference tests. The reference is not presented as our own custom model engine. A full engine will need GGUF/safetensors weight loading, tokenizer/chat-template parity, image/video preprocessing, vision transformer, projector, hybrid recurrent/full-attention language stack, sampling and state management. These cannot be replaced by synthetic outputs.

Alternatives considered: a full native engine before measurements delays useful evidence; a Python vLLM/SGLang harness violates the language requirement. Start with the native reference while keeping custom engine components independent. Do not port Baseten implementation files.

Hardware initially observed: RTX 5060, 8151 MiB, driver 580.178.04. No service interruption, GPU clock changes or global toolkit installation is required. Build tools and benchmark assets are isolated from application installations.

Success gate: at least 1.15× throughput or baseline/candidate latency at the same work and quality, repeated after fresh process startup in reversed order. The user's supplied post reports 15% over SGLang, not a universal hardware-independent gain. No claim that this figure has been independently reproduced.

## Research lead supplied by the user

[Ali / @waterloo_intern, post 2121391498159599785](https://x.com/waterloo_intern/status/2121391498159599785).

User-provided account: a purpose-built Rust DeepSeek engine reportedly took four days and about $500 of model tokens, beat SGLang by 15%, and its optimizations were later ported back to SGLang. Claimed techniques include specialized GEMV/MoE/collectives, one graph covering speculative draft/verification, fused residual-stream mixing and fused routing/expert execution. These are unverified reported figures, not our budget or schedule commitment.

Takeaway: fast experimentation and GPU work specialization matter; removing CPU abstractions alone need not help when GPU work dominates and CUDA graphs already remove launch overhead. Qwen3.5-4B is dense with hybrid attention; DeepSeek's MoE, routing and residual-stream-specific designs are not transferable implementations.

Primary implementation references: the pinned MIT llama.cpp source and Qwen model specification. Baseten's Elastic-licensed implementation is excluded. Model weights and all experimental quantizations retain their own provenance/licenses.

## Evidence boundaries

Synthetic image sequences establish timing and smoke correctness only. They do not validate native temporal video, real-world model quality or equivalence to the private fine-tuned scorer. Do not compare against historical NF4 numbers as if weights and inputs matched. GPU snapshots are not peak allocation. Errors, missing timings and cached prompt reuse fail the run rather than producing a misleading successful summary.
